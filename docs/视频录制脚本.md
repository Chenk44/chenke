# 演示视频录制脚本（尘客 · 7 分钟）

> 比赛硬要求：**5–8 分钟、MP4、1080p**，其中**至少 2 分钟**必须是「AI 协同过程复现」。
> 这份脚本按 7 分 10 秒设计，留了 50 秒余量——录长了不用剪得太狠，录短了也够 5 分钟。
> 旁白是逐字稿，可以直接念；括号里是操作，不用念出来。

---

## 二、分镜表（总长 7:10）

### 00:00 – 00:28　开场：先说问题，不要先放 logo

**画面**：一张静态页（可以直接用 `docs/evidence.html` 的「02 问题是真的」那一屏），或者你自己的群聊截图。

**旁白**：
> 周五晚上，群里问「周末去哪」，五个人各自发了链接，没人拍板。
> 四十分钟之后有人说「要不就海岸城吧」——不是因为合适，是因为不想再吵了。
> 大众点评回答「这家店好不好」，小红书回答「哪里好看」，
> 但没有一个工具回答「我们这群人今天该去哪」。
> 尘客解决的就是这一句话。

### 00:28 – 01:15　建局：30 秒开一个局

**画面**：首页 → 填局名 → 选出发商圈 → **选日期**（停 2 秒，让「小雨转中雨 28°/21° 雨天，方案会优先室内」这行出现）→ 填预算 → 点「创建并拿到邀请码」。

**旁白**：
> 建局只填四样东西：从哪出发、哪天去、人均预算、玩多久。
> 日期一选，系统自己去查那天深圳的天气——高德给三天，Open-Meteo 给七天，
> 下雨就自动优先室内，不用退出去查天气再回来。
> 拿到六位邀请码，发到群里，每个人点开链接自己填。

### 01:15 – 02:30　各填各的：三个滑杆 + 一句话

**画面**：点「我也要填」→ 拖三个滑杆 → 勾几个硬条件 → 在「或者直接说一句话」里输入
`想安静点，下雨别走太远，人均 100 以内，最好能待一下午`
（停顿看下面灰色标签一个个出现）→ 保存 → 回到局页（显示 5/5 已填）。

**旁白**：
> 每个人只填自己的口味：要多安静、舍不舍得花钱、愿不愿意跑远，再加几个硬条件。
> 不想拖滑杆也行，说一句话——它会被拆成结构化约束，
> 比如这句会变成「安静 0.85、人均上限 100、雨天优先室内」。
> 解析是本地规则做的，三毫秒，断网也能用。
> 注意这里不是让大模型推荐地点，它只负责把一句人话翻译成约束。

### 02:30 – 04:30　AI 协同过程复现（重点，满 2 分钟）

这一段是唯一能拿分也可能丢分的地方。**不要念文档，要讲「我当时怎么想、它怎么错、我怎么逼它改」。**
建议按下面四拍走，每拍 30 秒。

**画面 1（02:30–03:00）**：双击打开 `docs/ai-collaboration/02-预算语义.md`，滚动到「我的原话」和那张四层表。

> 这是真实发生过的一次事故。我在页面上看到：预算填 150，方案里三样东西分别 98、60、60，
> 每一项都没超过 150，加起来 218 却超了。
> 我把这句话原样丢给 AI：「这里你是怎么写的代码啊？逻辑判断是什么？」
> 它没有辩解，先把四层位置摆出来——第一层把日预算当成了单站上限，
> 第二层逐点判断，第三层方案层根本没有求和，第四层解释文案还在写「不超预算」。
> 四层错在一起，页面看起来很合理。

**画面 2（03:00–03:30）**：切到 `01-室内偏好.md` 的那张三层表。

> 还有一次是我说「不想去室内」，它还是推室内。我问它是不是没接 AI，
> 它给了一个我没想到的答案：接 AI 也修不好。
> 因为第一层是听不懂词，第二层是字段设计——`require_indoor` 是一个布尔值，
> 「不想去」等于「没说过」，第三层是数据，海岸城五个点全是室内。
> 于是我们改成三态：想出去是 -1，无所谓是 0，想待在室内是 +1，两个方向对称扣分。

**画面 3（03:30–04:00）**：切到 GitHub 仓库的 commit 列表，从最早那条往下滚。

> 这些都是那几天真实的提交，47 个，不是最后一天推上去的一大坨。
> 每一次提交对应一次对话：先改解析器，再改字段，再补数据，
> 每一步都能单独回滚，也能单独测。

**画面 4（04:00–04:30）**：切回编辑器，现场敲一条小指令（**不要超过 20 秒**），比如
`把方案卡上的共识度改成右对齐的等宽数字`
→ AI 改完 → 浏览器刷新，指着那一处变化。

> 这是现场演示：我说需求，它改代码，我刷新页面验收。
> 我的规矩是——它改完必须给我一条能自己跑的验证命令，
> 不然我默认它没改对。

### 04:30 – 05:40　结果页：三个方案，凭什么这么排

**画面**：局页三个方案并排。依次用鼠标指：
① 卡片顶部的「共识 74.4%」；② 「合计 ¥98 / 预算 ¥150」这个 chip；
③ 时间线第一站的时间；④ 解释卡里「最让步的是 小林（0.76）」。

**旁白**：
> 出来的是三个方案，不是一个——因为一群人需要的是选项，不是命令。
> 每个方案四件事：几点到哪、这一天人均多少（这里是 98，预算 150，没超）、
> 大家的共识度多少，以及最关键的一句：谁让步最多。
> 共识分不是平均分，是 0.6 倍平均加 0.4 倍最低分——
> 平均分高但把一个人坑惨的方案，排不到第一。
> 排序还会看营业时间：19 点出发，书店 21:30 关门，算法会自己把顺序调过来。

### 05:40 – 06:20　投票 + 数字背板

**画面**：点「投这个」→ 卡片变色、票数 +1 → 切到 `docs/evidence.html` 一页速览。

**旁白**：
> 群里投完，票数最高那个就是答案，页面上一目了然。
> 底下这些数字都能重算：200 个深圳地点、20 个商圈、127 个自动化测试、
> 一次推荐枚举 12,696 条动线，耗时 86 毫秒——
> 所以这里不需要遗传算法，穷举就够了。

### 06:20 – 06:55　复现：三条命令

**画面**：终端依次敲（**提前跑过一次，缓存好，不要现场装依赖**）

```
python -m scripts.seed        → 共 200 条
python -m pytest -q           → 127 passed
python -m uvicorn app.main:app --app-dir backend
```

**旁白**：
> 评委拿到仓库，三条命令就能跑起来：灌数据、跑测试、起服务。
> 不需要数据库服务，不需要外网，不需要 API Key——天气和高德只影响「有没有额外信息」，
> 不影响能不能用。

### 06:55 – 07:10　收尾：主动说局限

**画面**：停在首页或局页，不要淡出太早。

**旁白**：
> 我知道它的边界：只做了深圳；一句话解析是规则版，太绕的说法会听不懂；
> 营业时间不包含节假日。
> 但它解决的是那个真问题——让一群人的决定，从四十分钟变成三分钟。

## 三、AI 协同那 2 分钟的三种拍法（按省事程度排）

| 拍法 | 怎么做 | 优点 | 缺点 |
|---|---|---|---|
| **A. 文档 + 提交记录（推荐，必选）** | 打开 `docs/ai-collaboration/` 的三份 md + GitHub 提交列表 | 稳定、可控、不依赖网络和模型响应速度 | 静态，需要旁白撑住 |
| **B. 现场敲一条小指令** | 编辑器里输入一句小需求，等它改完，刷新验收 | 最有说服力，评委看到的是「真的在用」 | 模型偶发慢/改偏，要留 1–2 次重录 |
| **C. 屏幕录像回放** | 提前录一段真实对话（5–10 倍速播放） | 时间可控 | 二次压缩后字会糊 |

**建议：A 全程 + B 插 20 秒**。不要把整段都押在 B 上，模型一卡就得重录。

## 四、录制技巧（决定「像不像专业作品」）

1. **鼠标慢一点**：每次点击前停 0.3 秒，点完停 0.5 秒再动。录屏里最快的动作看起来都像手抖。
2. **不要念屏幕上的字**：念「这里填的是他们舍不舍得花钱」，不要念「人均预算输入框」。
3. **说话比画面快半拍**：先说要做什么，再做，观众才跟得上。
4. **一次录一段**：按上面的小节分段录，最后拼。错了只重录那 20 秒，不要从头来。
5. **终端命令提前跑一遍**：pip 装依赖、拉数据都会卡几十秒，录进去很难看。
6. **别出现敏感信息**：邮箱、真实姓名、API Key（`.env` 不要打开）、别人的聊天记录打码。
7. **画面上不要出现中文输入法的候选框**：录之前切到英文输入法，需要打中文时再切回来。

## 五、设备与软件

- **录屏**：OBS Studio（免费）首选；设置 → 输出 → 录像：`MP4`、编码 `H.264`、码率 `8000 Kbps`、`1920×1080`、`30 fps`。
- **备选**：Windows 自带 `Win + G`（Xbox Game Bar），只能在应用窗口内录，画质够用。
- **麦克风**：手机耳机麦也比笔记本内置好；离嘴 15–20 厘米，说话不要喷气。
- **剪辑**：剪映专业版（免费）足够：切段、加字幕、调音量。**字幕建议加**——评委看视频经常静音。

## 六、导出与自检

导出参数：`MP4 / H.264 / 1920×1080 / 30fps / 8 Mbps / AAC 192kbps`。

导出后逐条核对：

- [ ] 时长在 **5:00–8:00** 之间（目标是 7:00 左右）
- [ ] 分辨率 **1920×1080**（右键文件 → 属性 → 详细信息 → 帧宽度/高度）
- [ ] 有声音，且**全程音量一致**（不要开场大声后半段听不见）
- [ ] AI 协同那一段**单独计时 ≥2 分钟**（剪辑时掐表）
- [ ] 没有出现 `.env`、Key、真实姓名、别人的聊天记录
- [ ] 画面里能看清文字（手机上看一遍，看不清就重录放大）
- [ ] 文件名：`尘客-演示视频-1080p.mp4`

## 七、时间预算

| 环节 | 预计 |
|---|---|
| 准备（数据、窗口、软件设置） | 20 分钟 |
| 试录 1 分钟，回放检查声音画面 | 10 分钟 |
| 分段录制（8 段，含 1–2 次重录） | 60–90 分钟 |
| 剪辑（拼接、字幕、音量） | 40 分钟 |
| 导出 + 自检 | 20 分钟 |
| **合计** | **约 3 小时** |

留一个下午就够。**先录 AI 协同那 2 分钟**——它最容易翻车，先把它拿下，剩下的都是照着点鼠标。
