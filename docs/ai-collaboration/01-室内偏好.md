# 链 A ·「不想去室内」→ 三态偏好 + 地点库 49 → 200

> 时间跨度：2026-11-11 22:22 → 11-12 11:44（约 13 小时，含睡眠）
> 一句话：用户说「不想去室内」，系统照样推室内。真正的原因不是「听不懂」，而是**三件事同时坏着**。

---

## 1. 起点：两个 bug，一条不许动手的指令

**[11-11 22:22] 我：**

> 现在有几个问题，我先告诉你，你先不要急着修改代码，你先分析一下问题出在哪然后告诉我，
> 1.生成完一轮之后我无法退回主页面
> 2.我说不想去室内，但依旧给我推荐室内去的地方，甚至所有人都说不想去但依旧推荐，
> 截图这一栏我估计没起到作用，**你重点解释一下这一栏具体是怎么起作用的**

这句「你先不要急着修改代码」是刻意的：以前它一上来就改，改完我还得反过来验证它有没有改对。
这次先要诊断。

**[11-11 22:24] AI：** 给了三个独立缺陷，并且明确「代码一行没改」。其中问题一是两处叠加：

> **缺陷 A：路由把「没有 hash」当成了「回到上次那个局」**（`web/index.html:663`）
> ```js
> } else if (state.code) {
>   await loadGroup(state.code);   // ← 空 hash 时走这里，而不是 renderHome()
> ```
> 而 `state.code` 在页面初始化时就被 localStorage 填充了（`web/index.html:167`）
> `code: localStorage.getItem("zk_code") || "",`
> 所以只要你看过任何一个局，`state.code` 就永远有值，**空 URL 永远到不了首页**。

问题二它也给了三层，但**当时的判断是「解析器不认识词」为主**，建议加词表。
这个判断后来证明只对了三分之一。

## 3. 转折二：我问「能不能接 AI」，它给了一个我没预料到的回答

**[11-12 09:15] 我：**

> 我想问一下就是那个第二个bug，下面那一栏其实是没有接入ai的对吧，没法智能识别我说的话，
> 那有没有一种可能可以接入ai？**先设想，不要动功**

我原本的预设是「接个大模型就解决了」。它先确认事实：

> `backend/app/services/nlp.py` 一共 126 行，全是正则。它能识别的词表大小：
> **8 个字段、5 个忌口词、12 个天气词**。所以「可以去商场，不要玩桌游」这种话它一个词都不认识
> ——不是「识别错了」，是词表里根本没有「商场」「桌游」。

然后给了一个反直觉的结论，这段是整条链里最有价值的一屏：

> ## 但有个更关键的结论：只接 AI，这个 bug 还是修不好
>
> | 层 | 问题 | 接 AI 能解决吗 |
> |---|---|---|
> | 1. 听不懂 | 正则不认识「室内/户外/商场/桌游」，还把「不想去室内」读成 True | ✅ 能 |
> | 2. 数据模型 | `Preference.require_indoor` 是**布尔**，`False` 在 `algo/utility.py:118` 里完全无操作，等于「没提这件事」 | ❌ 不能，得改 schema |
> | 3. 数据分布 | 海岸城 5 个点**全部室内**，距离权重 0.30 全表最高 → 「近的优先」必然导向室内 | ❌ 不能，得改数据或权重 |

**这一屏改变了我的决定。** 如果只接大模型，等于花钱买了一个「听得懂但做不到」的功能。

## 4. 转折三：我选纯规则，并且要求同时扩充地点

**[11-12 09:18] 我：**

> 先做C. 纯规则增强，然后我想的是不止把负面规则增多，**我想把能去玩的地点再增加**，
> 你先帮我列出来可以做些什么

【AI】先划范围，指出两件事是同一个问题的两半：

> 「规则增强」和「加地点」其实是同一个问题的两半：规则决定**说不说得清**，
> 数据决定**说不清的时候有没有得选**。如果词表扩到能听懂「想在外面走走」，
> 但海岸城周边只有 5 个室内点，结果还是一样。所以这次两件事必须一起做，而且**数据先动**。

它给的否定引擎设计（后来原样落地）：

```
否定词：不 / 别 / 不要 / 不想 / 不去 / 不喜欢 / 受不了 / 讨厌 / 算了
作用域：否定词之后 6 个字以内出现的目标词才算被否定
三种动作：
  排除型   "不要玩桌游"     → exclude_categories += [桌游]
  反向型   "不想去室内"     → indoor_pref = -1
  降权型   "别太吵"         → quiet += 0.3（不是排除，是扣分）
```
> 还有一个必须修的分句问题——你测出来的那句之所以读反，是因为「不想去室内，但如果下雨就算了」
> 被当成一整句。正确做法是**按逗号句号切开逐句处理**，带「如果/那/要是」的句子标为 conditional。

**我砍掉了它的一个提议：** 它列了「`with_elder` 带长辈」这个字段。

**[11-12 09:28] 我：** 「with_elder没必要，你先验证一下高德api吧」

## 9. 这条链说明了什么

1. **现象不等于原因。** 用户的描述是「说了不想去室内，还是推室内」，
   但根因分布在 NLP、数据模型、数据集分布三处，只修任何一处都无效。
2. **AI 会倾向于修最容易修的那一层。** 加词表是最轻松的活，改 schema 最麻烦。
   是那句「只接 AI 也修不好」把它自己拦住的——但那也是我先问了「能不能接 AI」才逼出来的。
3. **人工标注不是脏活，是产品本身。** 9 个字段决定了「一群人决策」能不能成立：
   陌生人评分给不了「这台子吵不吵」，也給不了「这家带娃方不方便」。
